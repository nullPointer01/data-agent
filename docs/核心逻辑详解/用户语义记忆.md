# 用户语义记忆

## 目标与边界

语义记忆用于跨会话保留当前用户明确表达或高置信度识别出的稳定信息，分为三类：

- `PREFERENCE`：沟通风格、输出格式等长期偏好。
- `ENTITY`：称呼、角色、公司、行业、专业领域等用户画像事实。
- `CONCLUSION`：用户已经确认、后续仍有复用价值的决定或结论。

短期 `SUMMARY` 只服务近期上下文，不参与结构化画像。管理员仍只能治理平台资源，不能读取其他用户的个人语义记忆；所有查询、修改和删除都同时约束 `tenantId + userId`。

## 写入链路

一轮对话只有在会话消息真正持久化成功后才触发记忆捕获：

```text
AgentConversationRecorder
  -> ConversationMemoryCaptureService
       -> 同步保存 SHORT_TERM / SUMMARY
       -> 有明确“记住”意图
            -> SemanticMemoryExtractor 确定性提取
            -> SemanticMemoryService 幂等写入
       -> 普通对话
            -> SemanticMemoryExtractionJob 异步执行
            -> McpModelService JSON 模式提取
            -> SemanticMemoryService 校验并幂等写入
       -> UserProfileMemoryRefreshService 完整重建画像
```

明确记忆同步处理，保证用户刷新记忆中心后可以立即看到。普通对话的模型提取使用独立有界线程池，不阻塞本轮回答，也不占用已经结束的 Agent Run 预算；它仍执行用户 Token 配额、模型重试、用量记账和结构化日志。

## 提取准入

`SemanticMemoryExtractor` 对模型输出执行以下硬校验：

1. 一轮最多接收 3 条候选。
2. 类型只允许 `PREFERENCE / ENTITY / CONCLUSION`。
3. `semanticKey` 必须位于 `preference.* / profile.* / conclusion.*` 命名空间。
4. `evidence` 必须逐字存在于用户原话，助手回复不能作为事实证据。
5. 隐式候选置信度默认不得低于 `0.85`。
6. 密码、API Key、Token、身份证和银行卡等敏感信息不得写入。

显式规则会处理偏好否定和替换，例如“不要使用表格，改用列表”只生成“列表优先”，不会继续保留“表格优先”。“我是你的助手”一类助手自述也不能被识别为用户角色。

## 稳定键与覆盖

`memory_entry.semantic_key` 表示可覆盖属性，`confidence` 表示本条语义记忆的提取置信度。数据库唯一键为：

```text
(tenant_id, user_id, type, semantic_key)
```

同一用户再次表达同一属性时更新原记录及其向量，不新增重复记录。批内重复候选也会先按 `type + semanticKey` 合并。新建记录前执行用户记忆配额裁剪，覆盖已有记录不会误删其他记忆。

当前参与结构化画像的固定键包括：

- `profile.display_name`
- `profile.role`
- `profile.company`
- `profile.industry`
- `preference.communication_style`
- `preference.output_format`
- `profile.expertise_area.*`
- `profile.topic.*`
- `profile.data_source.*`

无法映射到具体画像字段的通用语义记忆仍可在分类卡片中查看和修正，但不会抬高结构化画像置信度。

## 画像重建

`user_profile` 是语义记忆的可重建投影，不是独立事实源。画像只读取长期 `PREFERENCE / ENTITY`，按更新时间倒序取最新值；摘要、结论和没有合法稳定键的旧记录均不参与投影。

每次新增、覆盖、修正、删除或清理语义记忆后，系统根据当前有效证据完整替换画像。没有实际投影成功的证据时删除旧画像，避免已经删除或修正的信息被历史快照永久合并回来。

## 用户纠错

记忆中心的偏好、画像事实和结论卡片展示来源、置信度和更新时间，并提供修正与删除操作。修正接口为：

```http
PUT /api/v1/memories/{memoryId}
Content-Type: application/json

{"content":"新的记忆内容"}
```

接口只允许当前用户修改自己的长期语义记忆，最多 500 个字符。修改后置信度置为 `1.0`、来源置为 `USER_EXPLICIT`，重新写入向量并重建画像。短期摘要只能删除，不能伪装成用户确认的语义事实。

## 数据库升级

新库由 `sql/init.sql` 创建字段和唯一键；已有数据库执行：

```bash
mysql -h127.0.0.1 -uroot -p data_agent < sql/upgrade-semantic-memory.sql
```

升级脚本幂等检查字段和索引。旧的错误 `user_profile` 可以精确删除，原始记忆无需清理；后续有效语义记忆会重新生成画像。

## 验收用例

1. 输入“请记住：以后回答保持简洁，优先使用表格”。
2. 记忆中心应出现两条 `PREFERENCE`，结构化画像显示“简洁直接 / 表格优先”。
3. 输入“请记住：以后不要使用表格，改用列表，并且需要详细说明”。
4. 原两条稳定键记录应被覆盖，记忆总数不因同属性重复增加；画像变为“详细解释 / 列表优先”。
5. 在卡片中修正任一语义记忆，刷新后内容、来源、置信度、更新时间和画像投影应同步更新。
6. 删除画像证据后，对应画像字段应消失；删除最后一条有效画像证据后 `user_profile` 不再保留空快照。
