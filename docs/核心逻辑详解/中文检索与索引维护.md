# 中文检索与索引维护

2026-10-03：ICU 镜像与索引契约、一次分块双索引、FILE/MEMORY 重建任务和评测工具已实现，干净编译与临时离线检查通过。Docker 未运行，实际插件部署、历史批次、`_analyze`、三组检索评测和浏览器引用验收尚未执行。

## 分块与分词的职责

中文分块使用 LangChain4j 官方递归 DocumentSplitter，中文句末边界由 DocumentByRegexSplitter 配置。`TextChunker` 保留章节、原文位置与父上下文。默认 500/100 是字符参数；框架内部重叠仍使用英文断句，不能把本次改造称为完整中文语义切分。

ES 分词发生在建立和查询倒排索引时。本轮固定 Elasticsearch 8.12.0 镜像安装官方 `analysis-icu`，自定义 `rag_icu` 使用 `icu_tokenizer + icu_folding`。ICU 对专业名词和技术编号的效果仍要看实际样本；插件安装成功不等于召回收益已验证。

## 当前入库调用链

```text
知识增改/同步，或文件创建/删除
  → MySQL 主数据 + IndexTaskStore（同事务）
  → IndexTaskWorker（原有有界池、租约、版本、重试）
  → IndexTaskProcessor（用任务保存的 tenantId/userId 读最新主数据）
      KNOWLEDGE → KnowledgeVectorIndexService
      FILE      → FileProcessingWorker → 官方文档解析器
  → RagDocumentIndexer
      TextChunker.split：一次生成全部分块
      清理旧全文 → 同一批块写 Milvus → 同一批块写 ES
```

两边使用相同 sourceId、chunkId、正文范围与结构元数据。文件向量保留原来的“文件[名称]”前缀；该前缀不改变原文偏移。空正文也清理两边旧块。任何删除、向量化或全文写入失败都传回任务；部分成功通过读取最新主数据重放收敛，没有跨存储原子事务。

文件上传不再另起 `FileProcessingSubmissionService` 异步链；删除也不再执行 `FileVectorCleanupService` 即时清理。文件处理状态仍记录 QUEUED/PROCESSING/COMPLETED/FAILED；持久任务状态是执行与重试的权威证据。

MEMORY 重建仅索引仍有效的 LONG_TERM 条目，优先使用 compressedContent，与正常长期记忆写入合同一致。不存在、过期或不再属于长期层的任务来源清理旧向量，不新增记忆全文索引。正常记忆提取的业务存储保持原链路。

## 索引契约与配置

公共显式配置在 `src/main/resources/application.yml`：

```yaml
app:
  rag:
    index-maintenance: false
    elasticsearch:
      index-name: data-agent-rag-v3
      analyzer: rag_icu
      contract-check-interval: 30s
```

`ElasticsearchIndexContract` 使用官方 typed SDK 定义 strict Mapping、字段类型、入库/查询 analyzer 和 `_meta` 版本。当前 schema=3、配置分块版本=cn-sentence-v1。首次与周期使用检查全节点 ICU 插件和实际索引；仅同名并发创建允许继续校验，其他异常明确失败。配置要求单一物理索引，不支持别名或通配符。

ES 文档主键包含类型、租户、用户、来源和块身份，避免同逻辑编号覆盖其他用户。检索仍强制 tenantId/userId 精确过滤。旧 v2 不自动删除，新索引契约也不证明历史 Milvus 已全部迁移。

## 部署与受控历史重建

先保存旧版本的隔离样本基线。改造后的严格契约不支持用配置开关重新启用 standard 旧索引；需要在旧 checkout/旧运行环境保存旧分块 + standard 报告，或另行准备明确的实验版本。为了使用本轮对照工具，旧实验版本需只移植新报告快照采集，保持旧分块/分词行为；已有缺字段的旧报告不能自动补字段后冒充公平基线。

1. 停止并排空所有应用实例的业务请求，再启动单独维护实例。把 `app.rag.index-maintenance` 改为 true 后重启；此配置不是在线开关。维护实例暂停定时知识同步、记忆维护与 Agent 审批恢复，IndexTaskWorker 继续执行以完成补偿。
2. Docker 启动后在仓库根执行 `docker compose up -d --build elasticsearch`。保留原 volume 和 v2 索引，不使用 `down -v`。这会重建 ES 容器；不是零停机操作。
3. 若数据库没有 index_task，先按原持久任务迁移要求执行 `sql/upgrade-index-tasks.sql`；FILE/MEMORY 是现有 varchar Kind 的新增枚举，不需要再建一张任务表。
4. 以来源所属的管理员身份获取 Token。管理接口仅 ADMIN 可用，并只列出/处理该登录用户自己的来源；不提供跨用户批量代管功能。其他用户历史不能用当前管理员 Token 代替身份重建。
5. 分页记录来源清单，按每批最多 50 个唯一 ID 提交，观察任务状态；全部目标版本收敛后关闭维护模式并重启，再验收引用和检索。

维护期间普通 `/api/v1/**` 返回 503；认证、索引管理和 GET `/api/v1/rag/health` 可用。这不会瞬间终止旧实例或在途请求，第一步的全实例停机不可省略。

接口调用示例（下列只展示合同，替换本人 Token 与实际 ID）：

```http
GET /api/v1/rag/indexes/maintenance
GET /api/v1/rag/indexes/sources?kind=KNOWLEDGE&limit=50&after=
GET /api/v1/rag/indexes/tasks?kind=KNOWLEDGE&limit=50&after=
Authorization: Bearer <ADMIN_TOKEN>
```

返回 `{items, hasMore, nextCursor}`，hasMore=true 时将 nextCursor 作为下一页 after。来源类型可选 KNOWLEDGE、FILE、MEMORY；不支持 CONVERSATION 重建。

```http
POST /api/v1/rag/indexes/rebuild
Authorization: Bearer <ADMIN_TOKEN>
Content-Type: application/json

{"kind":"FILE","sourceIds":["实际文件ID"]}
```

提交只入队；整个批次先按当前身份校验并锁定来源，任一无效或越权项拒绝整批。关闭维护模式时重建/重试返回 409。任务 FAILED 可用 `POST /api/v1/rag/indexes/FILE/实际文件ID/retry` 重置；RETRY 会自动退避，不必反复手工提交。SUCCEEDED 且 completedVersion=desiredVersion 才表示当前目标版本完成。来源和任务清单由操作者保存，本次未新增管理前端页面。

改变分块需要从原文重建 Milvus 与 ES。仅改变 analyzer 可通过 ES 重索引复用旧块，避免额外 Embedding 调用；但它不产生新的中文分块。本轮管理入口执行完整来源重建，可能调用外部 Embedding，未自动运行历史批次。Milvus 没有按分块版本隔离，因此回退分块也需在维护窗口重建，不能只切回 v2 就声称原子回滚。

## 黄金集与效果验收

复用 [教学材料](../../examples/rag-evaluation-lab/README.md)，上传六篇文档后可运行：

```bash
node scripts/rag-golden-dataset.mjs examples/rag-evaluation-lab/golden-dataset.template.json config/rag-golden-dataset.json --base-url http://localhost:8080
```

Token 只从工具进程的 `RAG_ADMIN_TOKEN` 环境变量读取，不输出；这是工具鉴权，不是新增应用配置。也可用 `--sources 本人的来源数组.json` 离线绑定。输出文件必须不存在，父目录须先准备。绑定严格拒绝缺失/重复来源，教学数据不等于真实业务黄金集；正式验收的五类问题各至少 6 条须人工另行标注。

应用从 `app.rag.benchmark.dataset-path` 加载黄金集（默认 `./config/rag-golden-dataset.json`），拒绝未替换占位 ID。同一管理员调用 `POST /api/v1/rag/benchmark/run`，保存原始 JSON 报告，可能消耗向量化/精排调用。

```bash
node scripts/rag-compare-reports.mjs baseline.json candidate.json
```

报告记录索引/analyzer、配置分块版本、字符大小/重叠、查询变换配置和实际检索问句；配置版本标签不证明历史块已更新。对照工具固定黄金集哈希、语料版本、模型、TopK、阈值和实际查询，仅允许索引/analyzer/分块变量变化；执行错误、精排降级或缺少新快照的旧报告拒绝比较。原有 Recall@20≥0.90、MRR@10≥0.75 门槛未降低。

三组顺序对照为旧分块 + standard、旧分块 + ICU、中文分块 + ICU。第二组仍需要固定旧分块的实验环境，当前主分支不会为此保留双分块引擎。至少相同预热下重复三轮，检查全组不退化、中文收益、编号/英文新增漏召回与 P95≤基线120%；脚本单轮差值不代替最终验收。

当前尚无真实收益数据。离线证据与限制见 [验证记录](../../openspec/changes/chinese-rag-index-upgrade/verification.md)。后续断点可放在 RagDocumentIndexer.replace、IndexTaskProcessor.process、ElasticsearchFullTextClient.ensureIndex、VectorMemoryService.searchMatches。
