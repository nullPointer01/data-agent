# Skill 程序性记忆与工具依赖

2026-10-14：Skill 继续保存在 MySQL。数据库适合多用户在线维护、归属隔离、候选审核和版本管理；运行时用官方 `Skill` / `Skills`，并不要求业务存储必须是文件系统。

## 职责与链路

个人事实、偏好和已确认结论仍属于语义长期记忆。Skill 保存可复用的方法和操作经验。Tool 执行动作，MCP 提供标准远程接入；Skill 声明的依赖既可以是本地工具，也可以是已注册 MCP 工具的稳定名称。

`skill_config.tool_dependencies` 每行一个工具名，最多 24 个。不得依赖激活、资源读取、学习和专家委派适配器。声明依赖不是授权；用户仍需给 Agent 显式绑定 Skill 和所需 Tool。

执行链路：

1. Router 选择技能管理入口，不必提前列出 Skill 内部每个业务工具；初始候选上限仍为 5。
2. ConfigurableAgentExecutor 将已绑定 Skill 的依赖与当前 Agent 可调用工具取交集，再按上下文合同去掉关闭的检索工具。这个潜在依赖池在本次执行开始时固化。
3. AgentToolInvocationContext 区分 `allowedToolNames`（潜在授权池）和 `initialToolNames`（初始可见工具），依赖规格带服务端 `skill_scoped_only` 标记，激活前隐藏。
4. 官方激活执行器经过 Pipeline，返回指令及 `activated_skill` 属性；失败结果不生成属性，不从自然语言中猜测激活状态。
5. 官方 `Skill.toolProviders` 和 `Skills.toolProvider` 检查原生工具结果属性，按已激活 Skill 动态提供依赖。GovernedToolSession 只交付自己的受治理执行器，不开放 SDK 原始执行器。
6. 模型提出的整批调用还须属于本轮可见工具，并经过权限、Schema、风险、审批、超时及根预算。缺少依赖会在激活结果中说明，不能假装执行成功。

运行中修改 Skill 不能扩大已固化的工具池；停用或删除技能后不再开放其专属依赖。已读文本仍可能在当前模型窗口内，不能将停用宣称为擦除模型已经看到的内容。普通已选业务工具与技能依赖重名时继续作为普通工具可见。

## 学习候选

两个入口共用 `SkillDraftGenerator` 的类型化 AiServices、原生 Schema 与严格输出校验：

- `proposeSkill`：给 Agent 显式绑定此工具后，Router/模型可以按需主动提议。USER_PROCEDURE 以用户真实的跨任务操作方法为来源；EXECUTED_WORKFLOW 从服务端 Journal 读取本次成功工具序列，至少两个不同的已绑定业务工具、Journal 未溢出才能提炼，模型不能伪造成功轨迹。两类都要求本轮用户目标原文证据，拒绝子 Agent 委派文本；不为每轮聊天增加学习模型调用，提炼费用计入当前 Run 和日配额。流程候选确认仍要求来源任务最终 COMPLETED。
- 聊天的“提炼为技能”：`POST /api/v1/my/skills/from-run/{runId}`。只读取本人 `COMPLETED` 的持久任务及对应已保存问答，不接受浏览器传来的执行结果。模型从这些资料提出通用方法，任务完成不代表答案已独立验证。

候选保存到同一 `skill_config`：`private_skill=true`、`review_status=PENDING`、`enabled=false`，附带来源 Run 和连续原文证据。每用户每 Run 最多一条、最多 50 条待确认候选；没有新建后台队列或周期扫描。模型提炼不是训练模型，也不能自动发布、绑定、覆盖已有技能或修改权限。

“上下文 → 技能经验”按页查看本人候选。检查并编辑名称、适用任务、指令、步骤和依赖后点击确认，转为 `PUBLISHED` 并启用；拒绝转为 `REJECTED`。确认时锁本人技能、重验来源任务完成和会话可读状态；删除来源会话或失败/等待审批的任务不能发布。发布后须在“我的 Agent”绑定技能及工具，未来请求才会看见它。

个人技能只向本人暴露，管理员共享技能维持旧用途；个人技能不会进入其他用户能力目录。已发布个人技能可以编辑、查看历史、回滚和删除。历史保存指令、步骤与工具依赖，回滚不能恢复旧权限。管理员“生成技能”也改为只返回可编辑草稿，点击确认创建前不写库、不启用。

## 审批恢复

Checkpoint v4 保存初始工具、潜在池和工具结果的激活属性，Supervisor 同时保存父初始工具，恢复重验原授权与当前权限并取交集。新配置不能扩充旧检查点的权限。原生续跑调用同一动态目录，不重放已经批准执行的动作。

继续读取 v1～v3：缺失初始工具字段时只使用旧检查点本来已有的白名单，不替旧消息补造激活状态。混用只支持 v3 的旧 Worker 与生成 v4 的新服务不可行。Supervisor 的深层嵌套审批限制保持原边界。

## 验收操作

新增 Flyway `V9__skill_dependencies_and_learning.sql`，本轮未执行，正常启动由 Flyway 执行。需要前后端及数据库同版。

1. 管理页创建“计算复核”，依赖填写 `calculate`；指令要求阅读步骤、调用计算工具并复核。Agent 绑定技能与 calculate。发送“使用计算复核技能计算 (120+80)*0.9”。检查激活前规格没有技能专属 calculate，激活后出现，结果为180；若 Router 独立选择了 calculate，它作为初始工具出现是正常行为。
2. Agent 只绑定技能，去掉 calculate。技能依赖不能授予计算权限，应看到缺失依赖说明，没有实际执行证据。
3. 用同一技能测试 searchKnowledge/searchMemory：上下文 OFF 时即使声明依赖也不能开放检索。
4. 给 Agent 绑定 proposeSkill。输入“以后做经营分析，先检查缺失值，再分析同比，最后复核图表；把这套方法整理为可复用技能”。应形成私有待确认候选。输入“我是 Java 开发”或“这一次用表格”不得生成操作技能。
5. 成功对话后点击“提炼为技能”，重复点击同一个 Run 返回原候选，不产生副本。到上下文检查修改后确认；发布前能力目录不可绑定，发布后本人可绑定，其他用户不可见。
6. 测试失败/待审批任务、别人的 Run、删除来源会话、拒绝候选和未知依赖，均不可越权发布。
7. 已发布技能修改依赖，历史应保存原依赖，回滚恢复原指令与依赖；删除后不再激活。
8. Skill 中使用既有审批工具，审批暂停后重启、批准，检查只续跑获批动作一次；普通 ReAct 与 Supervisor local_assistant 均测试初始隐藏约束与二次审批。
