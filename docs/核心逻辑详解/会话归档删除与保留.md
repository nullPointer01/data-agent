# 会话归档、删除与保留

本轮将聊天历史（用户看到的记录）与 ChatMemory（本次模型窗口）分开管理。MySQL 保留产品历史，模型仍只预填最近 50 条并经过 Token 准入；页面按游标加载，用户可以查看更早消息。

## 用户操作

| 操作 | 结果 |
| --- | --- |
| 归档 | 会话进入“查看归档”，历史仍可读取；恢复前不能发送新消息。存在运行或待审批任务时拒绝归档。 |
| 恢复 | 只把 ARCHIVED 恢复为 ACTIVE；不支持恢复已删除会话。 |
| 删除 | 标记 DELETED，立即禁止历史、重命名、新 Run 和本人 Run 证据访问；取消未完成审批/Run/提取任务，并清空提取任务载荷。 |
| 到期清理 | 默认删除 30 天后开始分批清理，正常/归档会话不自动过期。超长会话可能需要多轮。 |

归档是整理列表，不会降低数据库占用。删除不是业务回滚：已执行的改价、外部请求等不会撤销；已发出的模型请求也可能产生费用。删除会取消当前进程的关联 Run，其他节点通过数据库状态、租约及模型/工具调用前检查拒绝后续执行，不能声称能瞬间中断已发出的外部操作。

## 接口与页面

所有接口均在 `/api/v1/analysis` 下，按当前租户和用户校验归属。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /sessions?status=ACTIVE&limit=5&cursor=...` | 按最近活动时间和 ID 返回一批会话；`nextCursor` 为空表示加载完毕。status 只允许 ACTIVE/ARCHIVED。 |
| `GET /session/{id}` | 恢复登录前选中的会话，即便它尚未出现在列表首屏。 |
| `GET /session/{id}/messages?limit=50&beforeId=...` | 返回按时间顺序展示的一批消息；`nextBeforeId` 用于加载更早消息。 |
| `POST /session/{id}/archive` | 归档空闲会话。 |
| `POST /session/{id}/restore` | 恢复归档会话。 |
| `DELETE /session/{id}` | 删除会话；重复删除不延长保留期限。 |

侧栏保留“加载更多 / 收起”，不展示页码，后端每次只返回有限记录。“收起”只隐藏已经加载的行。消息区单独提供“加载更早消息”，加载后保持滚动位置。切换会话后过期响应不得覆盖当前消息；审批结果刷新保留已展开历史。历史读取失败会提示重试并暂时禁止发送，不能把加载失败当成空会话。

## 执行与并发约束

- `ConversationAccessGuard` 是运行准入边界，依赖主库仓储和 Run 注册表，不反向依赖 SessionManager、模型或工具，避免循环依赖。
- 创建持久 Run、注册活跃 Run、挂起审批、会话状态变更、回答保存及内容写回都通过同一会话行锁协调。删除先提交数据库状态，再取消本进程运行和失效缓存。
- 模型每次调用/重试、工具每次尝试及排队后实际执行之前重验会话；审批恢复同时重验身份、权限和来源会话，不能只信任旧 Checkpoint。
- 隐式记忆写回按“会话 → 提取任务 → 用户修订”加锁，删除完成后无法借旧任务追加记忆；归档允许此前已排队的提取完成。显式记忆保存同样重验来源会话。
- 晚到回答、Trace 和恢复进度不会再写入已删除会话；状态/CAS 冲突不得覆盖删除造成的取消终态。

## 清理范围与配置

配置在 `application.yml` 的 `app.conversation.retention`，local/prod 继承同一默认值：enabled=true，deleted-days=30，cron 每小时第 17 分钟，session-batch=10，row-batch=200。

调度通过 `(status, deleted_at)` 索引定位到期会话，每个会话独立事务，每张内容表最多删除 row-batch 条。依次清理消息、提取任务（包括失败任务载荷）、审批请求、Run Checkpoint、Trace 和短期摘要；确认关联内容全部清空后才删除会话行，不用级联一次删光大会话。多实例由会话行锁协调。没有新增每秒/每分钟扫聊天记录的调度。

个人长期记忆仍是独立产品对象，删除会话不删除已保存的用户偏好；需要忘记时在记忆页面或通过 forgetMemory 操作。Token 用量、审计记录、已执行的业务流水保留独立用途。管理员在保留期内仍可按原有权限查看取消的审批/Trace；本人会话/Run 接口不再返回已删除内容。

旧版 CONVERSATION 向量已无生产写入/检索入口，本轮不清理历史 Milvus 向量，不宣称完成全系统擦除或数据库磁盘文件即时缩小。

## 迁移与验收

Flyway V4 增加归档/删除时间、列表/清理/消息游标/关联任务索引。旧 CLOSED 从迁移当天转为 DELETED 并开始 30 天保留期，同时取消关联未完成任务；不在升级当天立即删除原聊天消息。正常启动由 Flyway 执行，无需再手工运行同一脚本。

本轮未添加测试类，未编译、打包、启动服务、执行迁移或调用真实模型；静态检查不代表运行验收通过。重启后人工验证：

1. 选择旧会话，归档后在“查看归档”看到它；可阅读，不能发送；恢复后可继续聊天。重新登录仍能找到选中的旧会话。
2. 有运行或待审批任务时归档应提示先停止/取消；删除会话后管理员看到审批执行状态取消，不能再恢复执行。换用户访问同一 ID 应被拒绝。
3. 删除后用原 ID 请求消息、重命名、分析和 Run 证据均不能获取/追加内容；删除期间晚到回答和后台记忆不能写回。
4. 超过 5 个会话时“加载更多 / 收起”正常；超过 50 条消息时可以逐批加载更早记录，审批刷新后旧历史仍在。
5. 在独立验收库准备超过保留期的 DELETED 数据后验证有限批清理及外键顺序；大于 row-batch 的会话跨多轮清理，ACTIVE/ARCHIVED 和 LONG_TERM 不受影响。不应为验收修改真实业务会话的删除时间。
