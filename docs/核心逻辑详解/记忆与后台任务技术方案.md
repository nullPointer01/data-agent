# 记忆与后台任务技术方案

2026-10-10 普通产品聊天也已接入持久 Run 提交队列，执行与连接分开；占位提示不生成摘要/长期记忆，最终回答更新原消息再按请求计划创建提取任务。与索引、记忆提取及审批恢复使用独立队列，状态与重试语义不同。新链路见 [后台 Run 与事件续读](./后台Run与事件续读.md)。

2026-10-10 后续批次已把批准动作的即时唤醒接入独立 RabbitMQ 恢复队列，恢复/过期扫描改为一分钟补偿；审批页面变化另用每实例广播队列。下文记录索引/记忆提取批次，审批执行及其 ACK 语义单独见 [审批事件与状态订阅](./审批事件与状态订阅.md)。

## 本轮目标

沿用 LangChain4j AiServices、受治理 ToolProvider、MyBatis/Flyway 与现有索引服务，完成以下替换，不新增第二套 Agent 执行器：

1. 删除无人消费的整轮问答向量写入。MySQL 聊天原文、当前会话窗口、个人长期记忆和知识库保留。
2. 显式保存/忘记个人记忆通过 saveMemory/forgetMemory 工具执行，结果先返回模型，再生成最终回答。新工具必须在 Agent 能力中显式绑定，不自动扩大已有授权。
3. Router 只输出 SKIP/BACKGROUND 提取建议，删除 WAIT 及回答后同步提取。后台候选与聊天消息同事务持久化，模型提取在事务外运行，校验和实际记忆写入在短事务内完成。
4. RabbitMQ 分发索引及记忆提取任务；持久任务表兼任待执行记录，事务提交后异步通知。消费者从数据库读取最新任务并 CAS 认领，成功或失败状态持久化后才确认消息。

## 消息与数据库的一致性

消息只携带数据库任务 ID，不包含用户正文、模型凭据或租户授权。数据库任务未完成前始终保留，发布确认不能将业务任务标为成功。事务回滚不发布；事务提交后发送失败、进程退出或消息被重复投递，由每分钟的低频补偿重新通知未完成/租约过期任务。任务执行失败有限重试，耗尽后保留 FAILED 并将消息送入死信队列。

本方案复用任务表作为可靠投递的恢复依据，不再额外保存一张“已发布事件”表。它允许重复通知，依靠租约、来源去重和版本校验收敛；不宣称外部调用 exactly-once。模型提取失败重试也可能再次计费。

索引工作线程改由 Spring AMQP 监听容器控制并发，移除旧索引线程池与两秒扫描。租约续期仅更新本机正在执行的任务；审批恢复调度不是本轮替换范围。

## 个人记忆的写入边界

保存工具只能从当前 Run 的真实用户原话提取，不能把工具返回、上传文档或助手补充当作个人事实；使用原有结构化提取器、逐字证据、表达行为、长期范围及敏感信息准入。返回主库保存数量与索引处理中状态，不把空候选当作成功。

子 Agent 收到的是模型生成的委派任务，不能拿它当作用户原话执行记忆写工具。显式保存模型调用前也快照修订，提交前重验，避免提取期间的用户删除/纠错被晚到显式结果覆盖；取消或预算终止后不继续提交工具写入。

忘记工具只接受已经取得的精确记忆 ID，重验当前用户归属，不提供模糊批量删除；缺少明确目标时先查询或澄清。记忆检索结果包含稳定 ID，工具描述准确区分个人事实与知识文档。

后台任务记录原始用户消息 ID 与请求开始时的用户记忆修订号。用户保存、修正、删除和清空记忆时推进修订号；后台提交时锁定用户记忆状态并核验修订号与已处理消息顺序。旧任务不能覆盖更新的记忆，也不能在用户删除后复活数据。写入期间不持有数据库锁调用模型或向量服务。

## 运行与验收

新增 Flyway 版本创建记忆提取任务和用户记忆修订状态表；既有索引任务继续使用。local/prod 使用显式 RabbitMQ 配置，Docker Compose 提供独立持久化 RabbitMQ 服务。已有 conversation 索引任务只标为取消，历史向量不在启动时批量删除，不再被读取或继续写入。

V3 还删除已停用的 `index_task.payload` 列，其中旧的完整问答加密副本随列移除；MySQL 聊天原文和其他业务数据保留。已经执行的 V1/V2 不改写。新旧应用不要混跑：旧版本仍会写入该列，应停止旧后端后再用新版启动升级。回退旧应用前需恢复 schema 兼容，不能直接降级二进制。

```bash
# 仓库根目录，只启动新增依赖，不重建其他容器、不删除数据卷
docker compose up -d rabbitmq
```

随后正常重启后端，由 Flyway 执行 V3；这次实现没有替你启动容器或执行数据库升级。Rabbit 管理页面为 `http://localhost:15672`，用户 `data_agent`，本地密码见 profile 配置；使用 `/data-agent` vhost。local/prod 按现有要求都采用同一本地连接初值，独立线上 broker 时修改 prod 配置，不在 IDE 环境变量中设置。

队列为 `data-agent.index`、`data-agent.memory-extraction`，各有 `.dead` 死信队列。使用持久 quorum 工作队列和持久消息，publisher confirm 与 mandatory return 只确认消息投递情况；业务状态以任务表为准。单机 Docker quorum 不等于已经部署多节点高可用。消费者数据库异常可能直接进入死信，但仍可由未完成主库任务补偿；最终失败记录不自动无限重试，需要处理原因后人工重放。业务失败指数退避从 5 秒起，实际重试由一分钟补偿唤醒，不能承诺五秒恢复。

## 如何使用和阅读

在“我的 Agent”设置中显式绑定 `saveMemory`、`forgetMemory`、`searchMemory`，运行模式使用自主决策或 ReAct；固定 CHAT 不执行工具。新工具是现有 LangChain4j `@Tool`，经 Registry、Schema、RBAC、能力白名单、预算和超时管道进入官方 AiServices。没有新增另一套 Function Calling。两种写工具都不自动重试，显式提取/删除确认调用计入当前 Run 预算；隐式提取重建后台用户身份，不复用已结束 Run。

建议按实际功能阅读：

| 功能 | 代码入口 | 要理解的边界 |
| --- | --- | --- |
| 是否后台提取 | PersonalAgentRequestPlanner / ModelSemanticRequestRouter | SKIP/BACKGROUND 与读取记忆独立；模型输出不等于授权 |
| 显式保存/忘记 | AgentTools / AgentMemoryToolService | 原始用户证据与实际工具结果；模型在事务外调用 |
| 聊天与后台任务原子保存 | SessionManager / ConversationMemoryCaptureService | 用户消息自增 ID 由主库产生，回滚不发布消息 |
| 可靠分发 | TaskSignalPublisher / BackgroundTaskConfiguration | Spring AMQP、提交后通知、数据库恢复依据 |
| 提取与陈旧写入保护 | MemoryExtractionWorker / SemanticMemoryService / MemoryWriteGuard | 先模型提取，后短事务核验租约、修订与消息顺序 |
| 向量投影与失败重试 | IndexTaskWorker / IndexTaskProcessor / IndexTaskStore | 当前主数据决定写入或清理，旧版本不能标记新版本成功 |
| 用户可见状态 | MemoryGovernanceService / MemoryPage | 已保存与向量索引完成分别展示，旧无任务数据显示尚未索引 |

## 手工验收输入与预期

| 场景 | 操作或输入 | 预期证据 |
| --- | --- | --- |
| 普通问答 | “SSE 是什么？” | 聊天原文和短期摘要保存；无隐式提取任务，无完整问答向量任务 |
| 显式保存 | “请长期记住，我希望你以后用简洁的中文回答。” | saveMemory 实际调用，返回 savedCount；记忆中心显示已保存及索引状态 |
| 不应保存 | “举例：用户说‘请记住我喜欢英文’，这种功能怎么实现？” | 不调用保存工具，不新增长期偏好 |
| 无绑定 | 关闭 saveMemory 后重复明确保存请求 | 不能声称已保存，后台也不能绕过绑定保存显式候选 |
| 隐式沉淀 | “我是 Java 后端开发，平时习惯简洁的中文回答。” | Router 为 BACKGROUND 时任务与聊天同事务提交，消费者提取稳定事实 |
| 忘记 | 索引完成后：“请忘记我偏好简洁中文回答这条记忆。” | 检索准确 ID，forgetMemory 校验并删除；多个目标时先澄清 |
| 陈旧任务 | 暂停提取消费，让隐式任务落库，再修正/删除已有记忆，随后恢复消费 | 原修订任务成功结束但不写回旧事实；最终主库与向量收敛 |
| 重启恢复 | 后台任务未完成时停止并重启后端 | 已提交任务可恢复，旧租约到期接管，重复通知不重复有效写入 |
| Broker 断线 | 暂停 RabbitMQ 后提交知识或 BACKGROUND 对话，再恢复 Broker | 主数据与任务仍提交；恢复后一分钟补偿重发，不依赖进程内队列 |
| 索引故障 | 暂停 Milvus 或 Embedding 后保存记忆，随后恢复 | 主库已保存，任务重试/失败有记录；页面不能显示索引完成 |
| 有限失败 | 让外部故障持续超过五次处理 | 主库 FAILED 和对应死信；不持续热循环重投 |

核对任务可按当前用户过滤 `memory_extraction_task` / `index_task`；Rabbit 面板可以观察队列，但不要把发布确认或队列为空当作业务成功。验收中的进程停止、服务暂停和重复投递都尚未执行。

必须验收：普通问答没有提取调用；明确保存工具真实成功后才确认；未绑定工具不能写；隐式提取重启可恢复；重复消息不重复执行有效变更；删除/修正与旧任务交错时旧数据不复活；RabbitMQ 断线时源数据与任务仍保存，恢复后收敛；外部索引故障进入重试/失败；个人记忆中心能区分保存与索引状态。

本轮遵守不新增仓库测试类、不主动编译/打包/启动服务的约定。源码、XML/YAML、引用与差异检查不等于运行验收。
