## 前一轮：Supervisor 检查点与审批续跑（2026-10-10）

本批为 Supervisor 的 local_assistant 和直接绑定专家补齐审批边界现场。官方 AgenticScopeSerializer 保存完成账本所在的 Scope，原父送模消息、决策历史、稳定节点目录、父/叶能力和待完成任务，与原叶工具对话/共享预算一起保存到 v3 加密 Checkpoint。恢复先重建当前用户身份、重验原节点归属与绑定、收窄原能力，再执行获批动作并续跑当前节点；节点完成后通过 beforeCall 导入应用完成事实，进入官方 Supervisor 新决策段，最后写回同一 Run/会话。

不导入框架私有 Planner 游标、不重放旧节点序列，不另写管理者循环/全局 Scope Store。相同节点与完全相同任务复用已完成结果；不同文本任务仍可能产生新执行，写操作继续依赖原审批授权/幂等下游。直接节点可再次审批，更深层专家委派缺少中间工具现场时仍在暂停前明确拒绝，不能宣称任意图恢复。

修复专家暂停被委派管道吞成普通失败/成功文本、正常暂停误记 FAILED、本地节点在判断暂停前检查 active、检查点误存父而非实际叶模型四处问题。审批阶段 Trace 保留 SUPERVISOR 引擎身份。根预算、取消和恢复租约继续复用；恢复段 token 尚未写入后台 Run 的完整事件日志，eventHistoryComplete 仍 false。

## 前一轮：长任务上下文摘要（2026-10-10）

本批修复“当前用户提问把全部后续工具历史绑成保护组”的问题。历史聊天继续整轮处理，当前任务按每批完整工具请求/结果分组；摘要和裁剪共用迭代分组实现，删除旧递归分组逻辑。系统规则、任务合同、当前问题、最近证据、未完成工具协议/审批和已加载 Skill 指令保持保护，保护内容放不下时仍明确拒绝。

超限才通过官方 AiServices、原生 JSON Schema 和统一严格 OutputGuardrail 生成摘录式摘要，复用当前回答模型。模型只能返回源位置与原文摘录，Java 核对连续原文、数量、长度和重复项，并从原消息补充工具身份；摘要作为不可信普通消息，不升级为系统指令或执行凭据。短请求不增加摘要调用，内部摘要无工具/会话窗口，也不能递归生成摘要。

根控制器内按模型、系统指令、当前问题、源位置/指纹和完整组边界复用；父子共享默认两次逻辑生成上限，同批候选不反复尝试，网络等待不持有状态锁。摘要走原模型治理、日配额预占/结算与根 Run 模型次数/Token/超时/取消，生成后重新核算预算。失败或预算不足退回完整组裁剪，取消/配额/记账/身份拒绝不能被降级吞掉。网络重试仍按既有规则每次尝试记账，不能把两次逻辑生成等同于两次厂商请求。

local/prod 均显式开启，公共默认输入 8192、输出 768、最小节省 1024、最多两次逻辑生成。SSE、Trace、个人 Run 安全投影和前端增加摘要状态/计数，不返回摘要正文。没有新增表或迁移，不改聊天原文与框架窗口；摘要缓存不写 MySQL、Milvus、画像或长期记忆。前一批 V7 仍待执行。

边界：本批是活动 Run 的送模副本压缩，不是跨会话摘要或跨进程摘要恢复。审批仍存原始现场，恢复后缓存/摘要次数重新建立，但持久根预算与日配额仍有效。原文匹配不保证摘录语义完整，输入/输出估算也不保证成本下降。详见 [长任务上下文摘要](../核心逻辑详解/长任务上下文摘要.md) 的链路、配置、七类人工验收与限制。

## 前一轮：每日 Token 原子预占与结算（2026-10-10）

本批将“先汇总明细再放行”替换为 MySQL 日账本行锁预占：以租户、用户、固定时区日期隔离余额；每次实际模型尝试独立 UUID，重试分别预占/结算，网络调用在事务外。使用 LangChain4j 官方 ChatRequest Builder 收窄输出上限，不丢失工具或 JSON Schema。模型客户端同时携带最终配置身份，回调不再重新读取完整模型配置。

完整响应按厂商用量或完整估算结算；发送标记前失败释放，标记后失败/取消/超时按整个预占额保守扣除并标记 UNKNOWN，不冒充真实用量。迟到完整响应可以校正日余额，不重新输出回答或恢复已终止 Run；根 Run 独立记账水位防止重复计数。结算、预占状态和明细同事务，记账故障不触发模型重试。临时模型连接探测也接入配额，仍不保存正文或缓存客户端。

## 一、已冻结的产品定位

Data Agent 是一个用于 Agent 开发岗求职展示的 **Java Agent Harness 参考应用**：

> 用户向自己的个人 Agent 提出问题或任务；Agent 自动判断是否使用模型、个人知识、工具或专家 Agent；结果带可核对的引用和运行证据；高风险动作先暂停并等待审批；管理员在 Control Plane 治理模型、能力、权限和运行质量。

它不是单一的企业问答 Agent，也不是把所有技术概念都暴露给普通用户的管理后台。普通使用面保持简洁，Harness 的工程证据收进管理控制面。

## 二、当前产品结构

### 普通用户

- **我的 Agent**：正式对话入口，配置名称、模型、System Prompt、能力包和已接入专家。
- **专家助手**：创建非默认 Agent Profile，作为受控子 Agent 供个人 Agent 委派。
- **知识**：录入文本或上传知识文档，进入个人 RAG 索引。
- **上下文**：管理会话与长期记忆。

个人 Agent 只暴露四类业务能力包：知识与记忆、文件理解、数据分析、专业技能。页面固定保存 `executionMode=auto`，普通用户不选 Chat/ReAct/Orchestrated、Token 预算和 Tool Schema。

### 管理员 Control Plane

- 运行与质量：运行追踪、动作审批、质量观测、Agent 评测、资源统计。
- 能力配置：模型目录、技能目录、知识与 RAG、数据连接。
- 平台治理：用户、用户 Agent、角色权限、审计。

Harness 管理的是“一次 Agent Run 能如何执行”；管理员管理的是“平台允许哪些用户和能力存在”，两者不是同一概念。

聊天回答不再提供点赞/点踩。对应按钮、前端请求、管理页面、后端接口和质量评分依赖均已移除；质量分只根据执行成功率、耗时和回退率计算。旧库如需物理删除历史反馈表，可手动执行 `sql/drop-agent-feedback.sql`。

所有实际数据表格默认按 10 条分页，可切换为 20 或 50 条；专家助手卡片列表使用相同分页交互，数据不足一页时不展示分页控件。会话列表不分页，默认展示最近 5 条，可展开全部并收起。首页固定数量摘要、质量建议、风险项和能力选择器不属于全量数据列表，不做分页。

内容：星河系统账户风控规则：手机验证码在30分钟内连续输错2次只记录风险日志，不会限制登录。连续输错第5次时，账户会被限制登录15分钟。人工解除限制时需要提供解除码 YM-2609。

手机验证码输错两次会触发限制吗？如果不会，第几次触发，限制多久？
