# Agent Harness 当前进度与验收交接

> 更新时间：2026-09-23
> 用途：作为新会话的唯一恢复入口，先验收再修复，不再重新设计产品方向。

## 一、已冻结的产品定位

Data Agent 是一个用于 Agent 开发岗求职展示的 **Java Agent Harness 参考应用**：

> 用户向自己的个人 Agent 提出问题或任务；Agent 自动判断是否使用模型、个人知识、工具或专家 Agent；结果带可核对的引用和运行证据；高风险动作先暂停并等待审批；管理员在 Control Plane 治理模型、能力、权限和运行质量。

它不是单一的企业问答 Agent，也不是把所有技术概念都暴露给普通用户的管理后台。普通使用面保持简洁，Harness 的工程证据收进管理控制面。

## 二、当前产品结构

### 普通用户

- **我的 Agent**：正式对话入口，配置名称、模型、System Prompt、能力包和已接入专家。
- **专家助手**：创建非默认 Agent Profile，作为受控子 Agent 供个人 Agent 委派。
- **知识**：录入文本或上传知识文档，进入个人 RAG 索引。
- **上下文**：管理会话与长期记忆。

个人 Agent 只暴露四类业务能力包：知识与记忆、文件理解、数据分析、专业技能。页面固定保存 `executionMode=auto`，普通用户不选 Chat/ReAct/Orchestrated、Token 预算和 Tool Schema。

### 管理员 Control Plane

- 运行与质量：运行追踪、动作审批、质量观测、Agent 评测、资源统计。
- 能力配置：模型目录、技能目录、知识与 RAG、数据连接。
- 平台治理：用户、用户 Agent、角色权限、审计。

Harness 管理的是“一次 Agent Run 能如何执行”；管理员管理的是“平台允许哪些用户和能力存在”，两者不是同一概念。

聊天回答不再提供点赞/点踩。对应按钮、前端请求、管理页面、后端接口和质量评分依赖均已移除；质量分只根据执行成功率、耗时和回退率计算。旧库如需物理删除历史反馈表，可手动执行 `sql/drop-agent-feedback.sql`。

所有实际数据表格默认按 10 条分页，可切换为 20 或 50 条；专家助手卡片列表使用相同分页交互，数据不足一页时不展示分页控件。会话列表不分页，默认展示最近 5 条，可展开全部并收起。首页固定数量摘要、质量建议、风险项和能力选择器不属于全量数据列表，不做分页。

“用户 Agent”是治理清单，不是第二套用户配置入口。管理员可按归属用户和角色查看全部 Agent、查看详情并跳转到该用户的运行追踪；不可新增、编辑或删除用户 Agent，只可启用或停用专家助手。每个用户的默认主 Agent 继续展示，但不能停用或删除；用户在“我的 Agent”修改配置后，管理员刷新清单即可看到同一份 Profile 的最新状态。

## 四、固定验收顺序

### 1. 本地能力介绍

在“我的 Agent”新对话输入：

```text
你能做什么
```

然后进入 `Control Plane -> 运行追踪`，打开最新 Trace。通过条件：

- 模式 `CHAT`，意图 `CAPABILITY_INTRODUCTION`，规则 `capability-introduction`。
- 模型、知识库、记忆和历史都关闭，候选工具为空。
- `modelCalls=0`、`toolCalls=0`、`tokens=0`、终态 `COMPLETED`。

### 2. 个人知识召回与引用

在“知识 -> 添加文本”录入：

```text
名称：星河账户风控规则
描述：用于验证个人知识库召回
内容：星河系统账户风控规则：手机验证码在30分钟内连续输错2次只记录风险日志，不会限制登录。连续输错第5次时，账户会被限制登录15分钟。人工解除限制时需要提供解除码 YM-2609。
```

先用“知识 -> 检索测试”确认索引存在，再用 `Control Plane -> 知识与 RAG -> 检索测试` 检查 Milvus 向量命中和 Elasticsearch 全文命中。

在“我的 Agent”输入：

```text
手机验证码输错两次会触发限制吗？如果不会，第几次触发，限制多久？
```

通过条件：答案为“两次不限制、第五次触发、限制 15 分钟”，页面显示“参考了你的知识库”，引用来源是“星河账户风控规则”。Trace 应显示 `PERSONAL_KNOWLEDGE + CHAT + knowledgeBase=REQUIRED`。

### 3. 同一 Run 的 Harness 证据

直接使用第 2 条产生的 Trace，不需要再发问题。通过条件：

- 有请求意图、模式、置信度、命中规则和资源开关。
- 有模型调用数、工具调用数、Token、耗时和终止原因。
- `runId` 与 `traceId` 使用同一标识。
- 终态为 `COMPLETED`，工具调用为 0，模型调用和 Token 大于 0。

### 4. 专家 Agent 委派

在“专家助手”创建：

```text
名称：酒店经营分析专家
简介：负责酒店经营指标查询和经营诊断
角色与要求：你是酒店经营分析专家。必须先获取经营数据，再计算指标变化，最后给出有数据依据的建议。
专长：数据分析
```

然后到“我的 Agent -> 设置 -> 专家助手”启用它，专家卡片应显示“已接入”。输入：

```text
请把任务委派给酒店经营分析专家：先查询杭州上周酒店入住率，然后计算与前期的变化，最后总结经营建议。
```

通过条件：模式 `ORCHESTRATED`，候选工具包含 `delegateToAgent`，工具治理证据中真实出现 `delegateToAgent`，
子 Agent 可继续调用已绑定的真实工具（如 `listDataSources` 或 `getCurrentTime`），父子执行共享根 Run。

### 5. 高风险动作审批与恢复

确认应用使用默认 `local` Profile 后重启即可，不需要在 IDEA Run Configuration 维护环境变量。使用两个不同账号：普通用户发起，管理员审批。发起用户的个人 Agent 需开启“专业技能”。输入：

```text
把演示酒店 HZ-001 的豪华大床房在 2026-09-15 的价格改成699元。
```

通过条件：

- 审批前 Run 为 `WAITING_APPROVAL`，页面提示需要人工审批。
- 审批前 `hotel_rate_sandbox` 没有对应记录。
- 另一个管理员在 `Control Plane -> 动作审批` 批准，发起人不能审自己的动作。
- 等待最多约 15 秒后，原 Run 恢复为 `COMPLETED`。
- 沙箱表只有 1 条对应动作，`after_price=699.00`，重放不重复写入。

## 五、执行纪律

1. 严格按 1 -> 2 -> 3 -> 4 -> 5 验收，不跳步。
2. 首次只跑 1 次；失败则只修当前链路，不增加新概念、不重构无关代码。
3. 修复后同一链路连续通过 3 次，再进入下一条。
4. 所有面试表述只基于实际跑出的页面、SSE、Trace 和数据库证据。
5. 失败时记录：验收编号、输入、用户页面结果、Trace 的“请求计划 / Run 预算与终态 / 工具治理”、后端最后一段完整异常。
6. 定位根因后的修复必须保持职责清晰和口径一致；禁止硬编码验收样例、简单调低阈值、复制同类逻辑或用兼容分支掩盖根因。
