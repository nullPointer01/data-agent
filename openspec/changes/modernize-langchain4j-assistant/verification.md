## 行为变化和局限

RRF 改为框架标准排名，不再混加向量与 BM25 原始分数。同通道重复候选只计一次。业务 `score` 投影仍为 0..1 排名分，不是相关概率；真实 Recall/MRR/NDCG/P95 未重跑。

聊天历史以原生角色进入模型，回答输入取消逐条 500 字截断，Token 治理仍可能裁剪较早消息。完整持久历史不受框架窗口淘汰影响。

普通 CHAT 的异步完成阶段已贯通至 SSE，模型等待期间释放 SSE 工作线程；规划、数据库、RAG 和可恢复工具循环仍有同步阶段。模型完成回调使用独立有界池，避免与等待模型的 ReAct 工作线程相互占池。StreamingHandle 只能在 SDK 提供后尽力取消底层连接。流式接入同一模型熔断状态，但不自动重试；失败的结构化日志 Token 字段仍为 0，实际用量或部分文本估算在独立 Token 账本中记录，不应从失败日志汇总成本。

普通聊天、路由和语义记忆提取采用 AiServices；结构化任务 Schema 生成和严格解析复用统一工厂。可持久化 ReAct 循环、业务输出准入、聊天表事务、结构感知分块、BM25 与精排降级继续由业务组件负责。RetrievalAugmentor 只在唯一 RAG 管道内编排，不在 AiServices 再发一次检索；未增加原始 `.tools(...)` 旁路。

故障治理状态由 Resilience4j 持有，计数窗口 N、最少样本 N、100%失败率保留最近 N 次逻辑调用失败后打开的语义，半开只放行一次；重试后的整体结果计一次，取消/中断/本地预算不进入厂商故障统计。异常提示、熔断探测行为与旧手写实现有所变化，真实服务指标和延迟需再次观察。
