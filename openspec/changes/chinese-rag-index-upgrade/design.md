# 中文检索与历史索引改造

2026-10-03 用户明确授权开始执行已讨论的《中文分块与检索改造规划》。上一轮官方中文分块已完成，本轮接续剩余实现，不重复迁移。

## 方案与边界

固定 Elasticsearch 8.12.0 官方镜像安装 analysis-icu。官方 Java SDK 创建 v3 索引：ICU tokenizer + ICU folding，index/search 同一 analyzer，身份 keyword、偏移 integer、结构 boolean、严格 Mapping 与 _meta 版本。首次与周期使用校验全节点插件、索引设置和 Mapping；仅并发创建的 resource_already_exists 可继续验证，其他异常不可仅凭索引存在吞掉。

统一 RagDocumentIndexer 一次分块驱动 Milvus 与 ES，保留元数据和文件前缀；替换知识与文件的二次分块。空正文清理旧索引，ES 失败传播；最终一致性仍通过已有 IndexTaskStore/Worker 租约与版本重放收敛。

文件上传任务纳入现有索引 Outbox，元数据创建/删除与 FILE 任务同事务；删除旧异步提交旁路。FILE 重建重新解析存储文件，MEMORY 重建只更新长期有效记忆向量。管理接口只处理当前管理员本人身份的精确 ID、最多 50 项，可分页列来源和任务；历史数据不自动改写。

维护模式为显式配置，重建要求维护模式开启；普通业务 API 拒绝新请求，认证/管理重建/健康可用。先停止原实例并启动维护实例，排空旧请求后操作；不是在线零停机迁移。索引 Worker 继续处理持久任务，失败可按原身份重试。

评测复用现有样本文档和固定黄金集合同，提供实际来源绑定工具及报告对照工具；禁止填占位 ID 当真实基线。报告补充索引/analyzer/分块/查询变换快照，三组对照必须固定模型、标注和查询。Docker 当前不可用，本轮准备代码和离线验证，不启动或覆盖用户历史索引，不编造真实 Recall/P95。

## 成功标准

由 Codex 在 JDK17 和临时离线验证执行：SC1 镜像/配置固定、SDK 索引契约校验能拒绝旧 Mapping、错误 analyzer、缺插件和并发错误；SC2 知识/文件一次分块，双索引 ID/正文/范围一致，失败不成功，空正文清旧块；SC3 文件任务与元数据同事务，FILE/MEMORY 按持久身份执行，维护与 ADMIN/分页/批量隔离正确；SC4 黄金集绑定不含占位 ID、报告快照与公平对照校验正确；SC5 编译、临时回归和中文学习/操作文档通过。真实 ES _analyze、三组黄金集及浏览器检查在环境恢复后执行，单独标未验。

不升级 ES 大版本，不引入另一套调度/分块/分词引擎，不新增仓库测试类，不删除历史数据库/索引，不承诺跨存储事务/原子发布。
