# 通用角色与 Agentic 专家委派工作流

用户授权：要求开始使用新 Agent 技术，并逐步解释改动及意义。沿用不增加仓库测试类、不堆重复实现、中文说明的要求。直接完成已授权的实现和验证，不重复申请同一范围审批。

本轮范围：先统一通用角色及能力约束，再把已有专家委派的规划→执行迁到官方 langchain4j-agentic 顺序工作流。不是演示入口，现有 delegateToAgent 必须实际经过框架。

## 设计

- 公共指令中立化，移除固定数据分析兜底、无条件 calculate 和强制一步一工具；由实际工具声明与服务端执行策略决定可用能力和顺序。
- 工厂默认角色统一引用公共常量。仅兼容识别旧版工厂默认个人提示词的精确文本，避免旧账号保留与审批冲突的内置规则；保留所有其他自定义角色，不批量覆盖数据库。
- 引入 langchain4j-agentic 1.20.2-beta30，与 Core 1.20.2 配套。该模块实验性，不宣称生产稳定。
- 新建 AgenticDelegationWorkflow，使用 @Agent 声明规划和专家执行节点，sequenceBuilder 定义顺序，@V/outputKey 在一次 AgenticScope 中传递已校验的 profile/context/plan/response。使用现有服务适配节点，真实 LLM 仍经受治理 AiServices。
- 父模型仍通过 Tool Calling 选择绑定专家。AgentDelegationToolService 继续执行绑定、租户、启用、任务长度校验；防环路/深度 Guard 包住整个工作流（包含规划），两个步骤进入时都检查根 Run。
- 工作流无 MemoryId、无持久化 Store、无额外线程/自动重试；状态仅属于本次委派。框架异常包装在边界解包，保留取消、预算和业务拒绝的类型。
- 不替换根 Run、审批存储、流式回答、RAG 或模型治理。不引入第二套持久化恢复。Supervisor、标准 MCP、Java/Spring 升级属于后续单独改造，本轮不顺手修改。

## 验收与边界

由当前实现代理在 JDK17 + 本地真实 agentic 框架、脚本规划/执行节点验证：节点严格按序、plan 原样传递、失败短路、取消不进入下一步、并发委派状态隔离；从真实 delegateToAgent 入口验证授权/租户/禁用/环路和深度拒绝、父请求不被修改、模型覆盖清空；编译及原有同步/Flux工具回归。

提示词检查覆盖空角色、自定义角色和旧工厂默认；检索和数据分析仍是工具能力，而非所有 Agent 的身份。

真实厂商/数据库/浏览器审批联调不在临时替身检查证明范围内。评估目标是学习并实际使用框架顺序工作流，不宣称已经实现 Supervisor、任意任务规划或跨进程 AgenticScope 恢复。
