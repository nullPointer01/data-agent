# Agent 上下文与混合路由现代化

## Objective

在保留现有 Spring Boot、LangChain4j 和自研 Agent Harness 的前提下，将请求规划从关键词驱动的三个布尔开关升级为可评测的结构化上下文计划。2026-09-23 修订：当前会话状态使用确定性策略，仅完整能力介绍保留本地快捷入口，其余请求根据已授权能力描述调用结构化模型路由；知识库和长期记忆既可预加载，也可作为受治理工具由 Agent 按需调用。

## Anti-Scope

- 不迁移到 LangGraph、Google ADK 或其他运行时。
- 不新增无约束自治 Agent，也不扩大现有子 Agent 可见范围。
- 不允许模型决定权限、预算、审批、状态迁移或幂等策略。
- 不为验收语句增加专用关键词或硬编码答案。

## Quantified Success Criteria

- SC1：需要模型回答时，有历史的同一会话生成 `REQUIRED` 的会话历史计划；空会话为 `OFF`。本地能力介绍不加载历史。
- SC2：执行计划使用 `REQUIRED/OPTIONAL/OFF` 表达知识库、语义记忆、用户画像和会话历史，不再以三个布尔字段作为内部决策合同。
- SC3：只有无文件的完整能力介绍可跳过 Router；其他请求调用结构化 Router，非法、调用失败或低置信度输出保守降级且不得扩大权限。业务意图和逐工具路由不保留关键词表。
- SC4：依赖前文的检索请求生成独立检索查询，原始用户问题保持不变。
- SC5：`OPTIONAL` 的知识库和语义记忆只能通过现有 Tool Registry、RBAC、Agent allowlist 和风险管道执行。
- SC6：Agent Eval 能记录并计算意图、模式和上下文计划匹配率；证据缺失显示不可用，不能按零分或满分误报。
- SC7（原始验收）：规划黄金集至少覆盖 30 个用例；规划相关测试与项目全量测试通过，前端生产构建通过。此项结果仅是 v4 历史记录。

2026-09-23 验证约束：用户后续明确要求删除测试类，`CLAUDE.md` 规定自动化 Agent 不主动运行测试、编译或构建。本轮不重建测试、不运行上述命令，以引用、合同和差异静态审查交付，并提供人工 Eval 输入。该约束不意味着 SC7 的运行验证通过；v5 模型准确率、延迟、审批恢复及编译兼容性仍未实测。实施/静态审查责任人为本会话实现者，环境为本地工作树；各 SC 的静态观察及待测项见 `routing-revision-verification.md`。

## Boundaries

### Always

- 保留现有 Run 预算、Checkpoint、审批恢复、Tool Journal 和 Trace 边界。
- 新增 Java 类型和非直观分支使用中文注释。
- 模型输出按不可信输入解析、校验并限制到现有能力集合。

### Ask First

- 无。本次范围已经由用户明确要求按既定顺序完成。

### Never

- 模型路由失败后 fail-open 到更多工具或更高风险模式。
- 将完整 Prompt、隐式推理或个人记忆正文写入 Trace。
- 回退或清理工作区中已有的用户改动。
