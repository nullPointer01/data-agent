## Why

Data Agent 已经具备统一 Agent Run、ReAct/Orchestrated 执行、工具治理、人工审批、持久化恢复、RAG 与 Trace 等 Harness 能力，但当前产品入口仍以聊天、知识库和多个后台功能页平铺呈现，无法让使用者或面试官快速理解 Harness 解决了什么生产问题。现在需要围绕“Java Agent Harness 参考实现”收敛产品主线，并补齐任务结果、运行证据和质量评测之间的闭环。

## What Changes

- 将产品主线收敛为“定义 Agent -> 发起任务 -> Harness 执行与治理 -> 返回结果和证据 -> 评价任务结果”。
- 把 `My Agent` 明确为 Harness 的参考应用，而不是整个系统唯一的产品定义。
- 重组普通用户与管理控制台的信息架构，突出 Agent 配置、任务执行、运行记录、审批和质量，而不再让内部能力平级堆叠。
- 在会话结果旁提供统一的 Run 摘要和事件时间线，展示执行模式、状态、预算消耗、知识证据、工具调用、审批、失败与恢复。
- 为 Agent Run 增加可选任务目标和成功标准，并记录最终结果状态，区分“模型回答结束”和“任务目标达成”。
- 建立 Agent 级评测入口，覆盖任务完成、工具选择、循环健康、审批触发、耗时与 Token 成本；RAG 指标作为其中一个维度而不是全部质量结论。
- 增加上下文治理证据，展示会话上下文的选择、压缩和 Token 节省情况；后续提供标准化工具扩展边界。
- 将统一能力目录推进为真正的 Agent 组合合同：用户可按稳定身份绑定 Tool、Skill 和子 Agent，Runtime 只执行当前 Run 重新解析后仍有权且可用的能力。
- 明确 `chat`、`react`、`orchestrated` 与 `auto` 的产品语义；子 Agent 委派共享根 Run 的预算和证据，并受深度与环路保护。
- 新增持续问题日志，逐项记录实现中发现的问题、根因、处理方案、验证证据和遗留风险。

## Anti-Scope

- 不建设 Dify 类拖拽式低代码 Agent 平台。
- 不把产品重新定位为单一数据分析助手、知识库问答工具或通用消费级聊天机器人。
- 不在本变更中承诺容器/虚拟机级强沙箱、完整事件溯源、多级审批或跨系统 exactly-once。
- 不重写已经存在的 ReAct、RAG、工具治理和持久化审批主链路；只有展示闭环或新契约确实缺失时才增量修改。
- 不在缺少真实数据的情况下宣称任务成功率、检索质量、成本或延迟已经达到生产指标。
- 不建设拖拽图、任意 DAG、跨 Run 消息总线或 Agent 市场；第一版组合仍由模型在受控能力集合内选择下一步。

## Quantified Success Criteria

- **SC-1 产品识别**：登录后的首屏在一个视口内同时呈现当前 Agent、任务输入、运行状态入口与 Harness 核心能力摘要，普通用户一级导航不超过 5 项。
- **SC-2 运行证据**：一次有效 Agent 请求结束后，界面能关联同一个 `runId/traceId`，展示至少状态、执行模式、耗时、模型调用数、工具调用数、Token 用量和终止原因 7 项运行信息。
- **SC-3 事件闭环**：运行详情能够按时间顺序区分至少 6 类事件：开始、路由/计划、知识检索、工具调用、等待审批或恢复、结束/失败。
- **SC-4 任务契约**：新请求可选携带任务目标和至少 1 条成功标准；执行结果明确返回 `ACHIEVED`、`NOT_ACHIEVED` 或 `NOT_EVALUATED`，旧请求保持兼容。
- **SC-5 Agent 评测**：同一评测报告至少输出任务完成率、正确工具选择率、无效循环率、审批策略准确率、P95 耗时和平均 Token 六类指标，并保留样本级证据。
- **SC-6 上下文治理**：长上下文运行可记录压缩前后 Token、保留消息数和压缩原因；没有触发压缩时明确标记而不是伪造收益。
- **SC-7 求职演示**：仓库提供 3 条可重复演示路径，分别证明知识证据、工具治理/审批、失败恢复/预算终止，每条路径都有预期现象和限制说明。
- **SC-8 问题闭环**：实现期间发现的每个实质问题都在 `problem-log.md` 中具有状态、根因、方案、验证证据和遗留风险；结束时不存在未说明的阻塞问题。
- **SC-9 能力绑定**：Agent Profile 可显式保存 0 至 64 个稳定能力身份，响应能无损恢复 Tool、Skill、子 Agent 三类选择；`NULL` 旧配置与显式空数组语义不同。
- **SC-10 受控组合执行**：模型只能执行当前 Agent 已绑定且当前用户仍有权限的 Skill/子 Agent；子 Agent 共享根 Run 的模型、工具、Token 与 deadline 预算，委派深度最多 3 层并拒绝环路。
- **SC-11 模式一致性**：`chat` 不调用能力，`react` 使用 Tool/Skill，`orchestrated` 额外允许子 Agent，`auto` 在存在子 Agent 且任务不是快速路径时选择编排模式；同步和流式遵守同一规则。
- **SC-12 可配置体验**：个人 Agent 设置可选择三类能力、显示已选数量与模式影响，不可用能力不能新增但可从旧绑定移除；目录加载失败时不能保存。

## Capabilities

### New Capabilities

- `agent-harness-workbench`: 面向普通用户和面试演示的 Agent 定义、任务执行、运行摘要与证据时间线体验。
- `agent-outcome-contract`: Agent Run 的任务目标、成功标准、结果判定及向后兼容契约。
- `agent-evaluation`: 基于可复现实例和运行证据的 Agent 级质量评测与对比报告。
- `agent-context-governance`: 长任务上下文选择、压缩、Token 预算及其可观测证据。
- `agent-extension-contract`: 用户或管理员扩展 Tool、Skill 与子 Agent 时的标准能力描述、权限和生命周期边界。

### Modified Capabilities

当前 `openspec/specs/` 尚无已归档基线规格；现有活跃变更保持独立，本提案不修改其规格文件。

## Impact

- 前端：`frontend/src/App.jsx`、导航、`ChatPage`、Trace/Quality/Approval 页面及相关样式；可能新增运行工作台组件。
- 后端：Agent Run 请求/响应 DTO、Run/Trace 查询接口、结果评估、上下文治理与评测服务；优先复用现有持久化与 Trace 数据。
- 数据：若任务契约或上下文证据无法可靠放入现有字段，将提供显式 SQL 升级脚本，不依赖 Hibernate 自动改表。
- 文档：更新 README、Harness 核心逻辑文档并新增三条演示手册。
- 依赖：第一阶段不新增前后端第三方依赖，后续阶段如需引入评测或协议依赖必须单独记录理由。

## Assumptions

- 具体假设及验证方式记录在 `sdd-assumptions.md`，实现中持续更新。
- 当前未提交修改均视为有效现状，所有工作在其上增量进行，不回退用户已有变更。
- 当前 Java 基线为 JDK 17，后端为 Spring Boot 3.2，前端为 React/Vite。
- 用户此前要求不新增或运行自动化测试、不编译后端；本变更继续遵守，除非用户后续明确修改该约束。

## Boundaries

- **Always**：保留租户、RBAC、工具白名单、审批和敏感数据脱敏边界；所有质量结论必须能追溯到真实运行证据。
- **Ask first**：新增依赖、删除数据库表或数据、修改现有公开 API 的不兼容字段、接入需要付费的外部服务。
- **Never**：把密钥、完整 Prompt、原始工具敏感结果写入 Trace 或问题日志；伪造评测结果；用前端隐藏代替后端授权。

## Verification Strategy

- 不新增或运行自动化测试，不执行 Maven 编译、打包或后端启动。
- 前端改动执行 `npm run build`，并在可用的本地服务上进行桌面与移动端浏览器检查。
- 后端改动通过结构化文件解析、调用链扫描、API/权限矩阵、数据库迁移审查和实际 Swagger/HTTP 演示进行验证。
- 每阶段把通过、失败与未验证项写入阶段验收记录，不以静态检查替代真实运行质量结论。
