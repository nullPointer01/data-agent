## 重启后人工验收顺序

1. 普通聊天输入“请解释 SSE 和异步任务的关系，用 Java 场景举例”。查看先出现规划阶段，再绑定 CHAT/REACT；Trace 的模型调用和 Token 包含实际发生的规划调用。规划时点击停止，确认不会继续回答或调用工具。
2. 同一会话追问“把刚才的例子简化一下”，确认历史角色有效；刷新或重新登录，确认保存的消息仍存在。成功回答持久化失败时应显示失败，而不是完成。
3. 添加名称“索引恢复验收”的知识，正文“编号 AGH-20260929 的退款时限为 6 小时”。观察等待索引 → 索引中 → 已就绪；之后问“根据我的知识库，AGH-20260929 的退款时限是多少”。修改为 24 小时，待新版就绪后再次查询。
4. 仅在独立验收环境模拟 Milvus/ES 不可用：任务应等待重试，达到上限后显示失败；恢复服务并点击“重试索引”。在索引处理中重启应用，租约过期后任务应被接管。删除知识后通过 GET `/api/v1/knowledge/index-tasks` 确认清理状态；失败清理可 POST `/api/v1/knowledge/{knowledgeId}/index-retry`。
5. 沿既有沙箱审批演示运行一次：审批通过后回复和状态更新，重新登录仍能看到最终消息；不要用真实外部写工具验收。
6. 在同一会话连续追问超过六条，再用较长内容观察上下文证据。裁剪应保留当前输入、系统约束和完整轮次；必要内容本身超限则明确拒绝。再执行既有 RAG 黄金集和 Agent Eval，与改造前结果比较。

## 保证边界

- H2 检查覆盖 SQL 状态语义，不代替目标 MySQL 版本、真实多实例负载和部署迁移验证。
- 模型等待可及时取消，SDK 中断/厂商停算属于尽力操作；已发出的请求可能仍消耗 Token，未返回 usage 时无法得到精确账单。
- Outbox 保证主库与任务同事务，数据库租约和版本防止旧执行冒领完成。Milvus/ES 不支持这里的事务与外部 fencing；替换仍有短暂缺失/旧结果窗口，不保证 exactly-once 或强原子发布。失租晚到执行会安排补偿，但“外部写已到达、旧进程随即崩溃且无法提交补偿”仍需真实故障演练或更强版本化索引发布解决。
- 普通请求仍有规划、数据库、RAG 等同步阶段，不是全链路非阻塞。
- 最终回答保存失败会传播；非最终审批进度消息仍保留原有尽力更新语义，权威状态以 durable Run 为准。
