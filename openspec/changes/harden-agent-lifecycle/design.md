# Agent 生命周期与可靠索引

## 授权与目标

用户在四项架构建议后明确“可以的，开始搞吧”。范围为规划与执行共用 Run、会话保存与后台索引分工、知识索引持久化恢复、Token 与历史窗口统一。按该授权实施，不重复申请方案权限；不新增仓库测试类，用临时可执行合同检查与构建验证。

## 实现约束

- 顶层规划必须在已注册、已启动的 Run 内进行。规划阶段不允许执行工具；完成后保留同一运行 ID、控制器和事件流，只绑定最终执行模式。
- 会话保存失败必须可见，不能继续报告成功；成功落库与待处理索引同事务提交。长期记忆立即生效的既有准入语义保留。
- 索引任务使用数据库保存状态、版本和重试。相同来源按顺序处理并支持幂等重放，后台线程不能借用其他用户权限。外部存储不宣称分布式事务或 exactly-once。
- 模型上下文统一使用框架 TokenCountEstimator 入口，未知模型使用保守估算。历史按预算选择完整会话轮次，工具调用与结果不能拆开。
- 不增加模型厂商、不升级 Spring/JDK、不运行真实用户数据迁移或清理、不提交 Git。

## 验收

本会话负责：JDK17 编译；临时脚本验证规划耗用预算与取消、保存失败、任务重放/重试/隔离、Token 长串输入与完整消息组边界。真实模型、Milvus、ES、数据库集成结果必须单独记录，不能用编译代替。
